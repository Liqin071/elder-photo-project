# 上线安全加固清单(阿里云 ECS:60.205.13.93)

> 背景:公网实测发现 4 个端口可从外部连通 —— **22(SSH)、80(Nginx)、8000(uvicorn 直连)、38221(宝塔面板)**。
> 其中 **8000 与 38221 是高风险项**:8000 绕过 Nginx(无 HTTPS/无限流),38221 是管理面板(被扫到即重点攻击目标)。
> 用法:上线前逐条执行并勾选;★ 标记为**必做**,其余按需。

---

## 一、端口与安全组(第一道防线,最有效)

### 1.1 目标暴露面

| 端口 | 服务 | 上线后 | 处置 |
|------|------|--------|------|
| 22 | SSH | 保留 | ★ 限来源 IP(只允许你的常用 IP)+ 改密钥登录 |
| 80 | Nginx | 保留 | 保持,仅用于 301 跳转到 HTTPS |
| 443 | Nginx HTTPS | 需开放 | ★ 备案+证书就绪后开放 |
| **8000** | uvicorn | **关闭对外** | ★ 应用改为只监听 `127.0.0.1`,安全组删除 8000 规则 |
| **38221** | 宝塔面板 | **关闭对外** | ★ 安全组只放行你的 IP,或改端口 + 开面板 SSL |
| 3306 | MariaDB | 未对外(已安全) | 保持,并确认只监听本机 |

### 1.2 阿里云控制台 → 安全组(入方向)最终规则

| 协议 | 端口 | 授权对象 | 说明 |
|------|------|----------|------|
| TCP | 443 | 0.0.0.0/0 | HTTPS 对外 |
| TCP | 80 | 0.0.0.0/0 | HTTP 跳转 |
| TCP | 22 | **你的固定 IP/32** | SSH 只允许自己 |
| TCP | 38221 | **你的固定 IP/32** | 宝塔面板只允许自己(或直接删掉) |
| ~~TCP~~ | ~~8000~~ | ~~0.0.0.0/0~~ | **删除** |
| ~~TCP~~ | ~~888/8888~~ | — | 宝塔默认端口,如存在一并删除 |

> 若你的家庭/办公 IP 是动态的,可临时放行 0.0.0.0/0 但**必须**配合密钥登录 + fail2ban(见 §四)。

### 1.3 服务器本机防火墙(双保险)

```bash
# 查看当前规则
firewall-cmd --list-all            # CentOS/Alibaba Cloud Linux
# 或
ufw status                         # Ubuntu/Debian

# 只放行必要端口(若启用了 firewalld)
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --permanent --remove-port=8000/tcp
firewall-cmd --reload
```

## 二、应用层:让 uvicorn 不再对外暴露 ★

编辑 systemd 服务(`/etc/systemd/system/elder-photo.service`),把 `ExecStart` 的 host 改为回环地址:

```ini
ExecStart=/usr/bin/python3 -m uvicorn app:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips=127.0.0.1
```

> `--proxy-headers` 让后端能取到 Nginx 透传的真实客户端 IP(登录限流、日志依赖它);
> `--forwarded-allow-ips=127.0.0.1` 表示只信任本机 Nginx 的转发头(防伪造)。

生效:

```bash
systemctl daemon-reload && systemctl restart elder-photo
ss -tlnp | grep 8000        # 应显示 127.0.0.1:8000,不再是 0.0.0.0:8000
```

同时检查 `.env`:

| 变量 | 要求 |
|------|------|
| `SECRET_KEY` | ★ 强随机(`openssl rand -hex 32`),不得用默认值;泄露=任何人可伪造登录 token |
| `DEBUG` | 必须 `False` |
| `DB_PASSWORD` | ★ 改强密码(见 §六) |

## 三、Nginx 加固

在 HTTPS 站点配置中补充:

```nginx
# 隐藏版本号
server_tokens off;

# 安全响应头
add_header X-Content-Type-Options nosniff;
add_header X-Frame-Options SAMEORIGIN;
add_header Referrer-Policy no-referrer;

# 上传体积限制(与后端 ≤20MB 对齐,留余量)
client_max_body_size 25m;

# AI 修图接口是成本入口:加限流(每分钟 10 次/IP,突发 5)
location = /api/ai/enhance {
    limit_req zone=ai burst=5 nodelay;
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 120s;
}

# 登录接口防爆破(与后端限流叠加,每分钟 20 次/IP)
location = /api/auth/login {
    limit_req zone=login burst=10 nodelay;
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

`limit_req_zone` 需定义在 `http {}` 块中(`/etc/nginx/nginx.conf`):

```nginx
limit_req_zone $binary_remote_addr zone=ai:10m rate=10r/m;
limit_req_zone $binary_remote_addr zone=login:10m rate=20r/m;
```

检查并重载:`nginx -t && systemctl reload nginx`

## 四、SSH 加固

```bash
# 1. 确认密钥登录可用后(别先关密码就锁死自己!)
ssh-copy-id root@60.205.13.93        # 或手工把公钥写入 ~/.ssh/authorized_keys

# 2. 编辑 /etc/ssh/sshd_config
PermitRootLogin prohibit-password     # 或改为密钥专用账号 + sudo
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
LoginGraceTime 20

# 3. 生效前用另一个终端验证密钥能登录,再:
systemctl restart sshd
```

可选加固:

```bash
# 改 SSH 端口(如 22022)后同步更新安全组,注意宝塔/脚本里的端口引用
# 安装 fail2ban:连续失败自动封 IP
yum install -y fail2ban || apt install -y fail2ban
systemctl enable --now fail2ban
fail2ban-client status sshd
```

## 五、宝塔面板(38221)★

| 项 | 做法 |
|----|------|
| 暴露面 | 安全组**只放行你的 IP**;或改用跳板/内网访问 |
| 端口 | 面板设置 → 改端口为不常见端口 |
| SSL | 面板设置 → 开启面板 SSL(HTTPS) |
| 账密 | 强密码 + 开启二次验证;不要用文档里记录过的旧密码 |
| 不必要服务 | 关掉面板里不用的 PHP/数据库管理(phpMyAdmin 也是攻击面) |
| 面板入口 | 建议设置"面板 SSH 登录限制/授权 IP" |

> 如果宝塔只是用来方便看文件,上线后可以直接卸载,改用命令行 + systemd 管理(本项目已全部脚本化)。

## 六、数据库(MariaDB)★

```bash
# 1. 确认只监听本机
grep -r "bind-address" /etc/mysql/   # 应为 127.0.0.1
ss -tlnp | grep 3306                 # 应为 127.0.0.1:3306

# 2. 用专用账号替代 root(最小权限)
mysql -u root -p -e "
CREATE USER 'elder_app'@'localhost' IDENTIFIED BY '<强密码>';
GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,ALTER,INDEX ON elder_photo_db.* TO 'elder_app'@'localhost';
FLUSH PRIVILEGES;"

# 3. 改 root 强密码 + 清理匿名/远程账号
mysql -u root -p -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '<新的强密码>';"
mysql -u root -p -e "SELECT user,host FROM mysql.user;"   # 不应有 '%' 的 root
```

改完把 `.env` 里的 `DB_USER`/`DB_PASSWORD` 换成新账号,重启服务:

```bash
systemctl restart elder-photo && curl -s http://127.0.0.1:8000/health; echo
```

## 七、备份(不做备份,加固做得再好也白搭)

```bash
# 每天 03:10 备份数据库 + 上传文件,保留 14 天
cat > /root/backup.sh <<'EOF'
#!/bin/bash
set -e
D=$(date +%F)
mkdir -p /root/backups
mysqldump -uelder_app -p'<密码>' elder_photo_db | gzip > /root/backups/db_$D.sql.gz
tar czf /root/backups/uploads_$D.tar.gz -C /home/elder_photo_project/backend uploads
find /root/backups -type f -mtime +14 -delete
EOF
chmod +x /root/backup.sh
(crontab -l 2>/dev/null; echo "10 3 * * * /root/backup.sh") | crontab -
```

★ 更稳的做法:备份同步到**阿里云 OSS**(`ossutil cp` 或宝塔的 OSS 插件)——机器被删/被黑时本地备份一起没了。

**恢复演练**(上线前做一次,确认备份真的能用):
```bash
gunzip -c /root/backups/db_YYYY-MM-DD.sql.gz | mysql -uelder_app -p'<密码>' elder_photo_db
```

## 八、代码里已经做掉的防护(免重复劳动)

| 项 | 实现位置 | 说明 |
|----|----------|------|
| 登录防爆破 | `utils/ratelimit.py` + `/auth/login` | 同用户名+IP 连续失败 10 次(5 分钟窗口)锁定 10 分钟,返回业务码 **4003**;成功登录清零 |
| 鉴权边界 | `utils/permissions.py` | 身份一律取自 token;未登录/失效 → HTTP 401;越权 → 业务码 2003 |
| 密码存储 | `utils/auth.py` | SHA256 预哈希 + bcrypt 加盐(规避 bcrypt 72 字节上限) |
| 上传校验 | `api/photos.py` | 内容类型+扩展名双校验、≤20MB、UUID 重命名、服务端生成缩略图 |
| AI 成本保护 | `api/ai.py` | 按用户每日次数上限(`AI_DAILY_LIMIT`,默认 20) |
| 错误信息 | 全局异常处理器 | 登录失败统一"用户名或密码错误"(防账号枚举);业务失败 HTTP 200 + 中文 message |
| 软删除 | `users.is_active` | 删档案/删志愿者改为停用账号,保护外键与历史数据 |
| 敏感信息 | `.env` + `.gitignore` | 数据库口令、微信 AppSecret、AI 密钥只存服务器,不入库不入仓库 |

## 十、异常时的快速自查

```bash
# 谁在连我(异常 IP 尝试)
journalctl -u elder-photo --no-pager | tail -50
grep "Failed password" /var/log/secure | tail -20      # SSH 爆破迹象
lastb | head -20                                        # 失败登录记录

# 异常进程/外连
ps aux --sort=-%cpu | head
ss -tunp | grep ESTAB

# 定时任务是否被塞后门
crontab -l; ls -l /etc/cron.*
```

发现被入侵的处置顺序:①拔网线式止损(安全组全关,只留你的 IP)→ ②改所有口令与密钥(SSH/DB/面板/微信 AppSecret)→ ③从备份恢复到干净环境 → ④复查代码与定时任务。
